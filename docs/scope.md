# 기능 범위와 일정

MVP와 확장의 경계, 주차별 작업, 동결 규칙.

- 관련 설계 결정: **D1~D6**
- 완료 지점: 스토어 출시 (운영은 범위 밖)
- 최종 수정: 2026-09-16

---

## 1. 동결 규칙

> **6주차에 MVP를 동결한다. 이후 새 기능을 추가하지 않는다.**

1인 11주에서 가장 큰 위험은 기술 난이도가 아니라 **기능 욕심**이다.
7주차 이후는 출시 요건·안정화·실험·배포에만 쓴다.

동결 이후 발견된 아이디어는 전부 `확장`으로 기록하고 손대지 않는다.

## 2. MVP

### 2-1. 핵심 흐름

| 기능 | 비고 |
|---|---|
| 현재 위치 획득 | OS 위치 서비스. 좌표 스무딩 포함. **지도 SDK 불필요** |
| 300m 주변 메시지 조회 | 유지 반경 450m. 기본값이며 9주차 실험으로 확정 |
| 메시지 작성 | |
| 영구 저장 | D3. TTL 없음 |
| 시간순 스크롤 + 페이지네이션 | 커서 기반 |
| 시간 구분선 | 이 서비스의 시그니처 UI |
| 익명 표식 | D4. 도형 6 × 색 4, 구간 단위 |
| **인용 답글** | 이름이 없을 때 대화를 해독하는 유일한 장치 (D4) |
| **인앱 답글 표시** | 앱 실행 시 "내 글에 답글 N개". 푸시 없이 조회만 (D6) |

### 2-2. 기반

| 기능 | 비고 |
|---|---|
| PostgreSQL + PostGIS | `ST_DWithin` + GiST 인덱스 |
| 접속자 위치 저장소 | `PresenceStore` 인터페이스. B(PostgreSQL)로 시작해 8주차에 A(Redis) 추가 → [`tracks.md`](tracks.md) |
| WebSocket + 선택적 브로드캐스트 | 프로젝트의 기술적 중심. 실험 1의 대상 |
| **`/config` 엔드포인트** | 없으면 9주차 반경 실험이 불가능 |

> **WebSocket에 대한 메모** — 사용자가 적은 초기에는 실시간 전달이 거의 발생하지 않으므로
> *사용자 가치* 기준으로는 확장에 가깝다. 그럼에도 MVP인 이유는 **프로젝트의 기술적 정체성**이기
> 때문이다. 시간이 부족해 무언가를 포기해야 할 때 이 구분이 판단 기준이 된다.

### 2-3. 안전 · 출시 요건

| 기능 | 비고 |
|---|---|
| 본인 글 삭제 | 기기 익명 키로 식별 |
| 신고 + **누적 자동 블라인드** | 1인 운영이라 수동 24시간 대응이 불가능 |
| 차단 | 스토어 심사 필수 |
| 관리자 숨김 | |

| **개인정보처리방침** | 스토어 등록 시 URL 입력 필수 |

| 기능 | 비고 |

## 4. 주차별 일정

| 주차 | 작업 | 완료 기준 |
|---|---|---|
| **01–02** | 뼈대 — Spring Boot · PostgreSQL+PostGIS · Redis · React Native · Docker Compose<br>계정·도메인·Oracle 인스턴스 확보, 상표 검색 | 앱 → 현재 위치 → 서버 통신 성공 |
| **03** | 공간 조회 — `ST_DWithin` 300m, Redis GEO, `/config` + A/B 그룹 배정 | 현재 위치 → 300m 메시지 |
| **04** | 메시지 CRUD — 쓰기·읽기·삭제, 커서 페이지네이션, 시간순 스크롤, 시간 구분선, 익명 표식, 인용 답글 | 스크롤 화면 동작 |
| **05** | WebSocket — GEOSEARCH 세션 선별, reconnect·heartbeat·미수신 복구<br>**서버 1차 배포** (Nginx, Let's Encrypt, WSS) | 외부 접속 가능한 서버 |
| **06** | 실기기 테스트 — 갤럭시 2대 300m 실측, 이동에 따른 변화 확인, 로그 수집 계측<br>→ **비공개 테스트 개시** | **MVP 동결**<br>14일 시계 시작 |
| **07** | 출시 필수 — 신고·차단·삭제·관리자 숨김·EULA·약관·개인정보처리방침·금지 구역 | 심사 요건 충족 |
| **08** | 안정화 — 새 기능 금지 | **프로덕션 권한 획득** |
| **09** | 실험 — 반경 A/B 분석, 브로드캐스트·공간 검색 측정 | 반경 최종값 확정 |
| **10** | 최종 배포 + 스토어 제출 — 확정 반경 반영, CI/CD, 통합 테스트 | 심사 통과 |
| **11** | 출시 + 발표 준비 | 프로젝트 완료 |

### 4-1. 배포가 5주차인 이유

```
서버 배포 → 비공개 테스트 개시 → 14일 → 프로덕션 권한 → 출시
```

비공개 테스트는 테스터 12명이 **실제로 앱을 쓰는 것**이므로 서버가 인터넷에 있어야 한다.
로컬 서버로는 불가능하다. **배포는 마무리 작업이 아니라 테스트의 전제조건이다.**

또한 10주차에 배포를 처음 해보면 도메인·인증서·방화벽·CORS에서 하루씩 소모된다.
WebSocket을 만들면서 어차피 WSS가 필요하므로 5주차에 함께 처리한다.

### 4-2. 실험 데이터는 6~9주차에 쌓인다

9주차는 **수집이 아니라 분석** 주차다. 데이터는 비공개 테스트 기간 내내 축적된다.
따라서 `/config`(3주차)와 로그 수집(6주차)이 **비공개 테스트 개시 이전에** 들어가야 한다.

### 4-3. 8주차 안정화 체크리스트

- [ ] GPS 오차 — 정지 상태에서 화면이 흔들리지 않는가
- [ ] 네트워크 끊김 — 오프라인에서 복귀 시 동작
- [ ] WebSocket reconnect — 재연결 후 미수신 메시지 복구
- [ ] 앱 종료 / 재실행 — 상태 복원
- [ ] Wi-Fi ↔ LTE 전환 — 소켓 유지 또는 재연결
- [ ] 위치 권한 거부 — 앱이 죽지 않고 안내 화면을 보여주는가
- [ ] 서버 장애 — 타임아웃 처리와 사용자 안내

## 5. 시간이 부족할 때 포기하는 순서

일정이 밀렸을 때 판단 기준. 위에서부터 먼저 포기한다.

1. 인앱 답글 표시 *(재방문 구조는 손실되나 앱은 동작)*
2. 금지 구역 수동 등록 UI *(DB 직접 조작으로 대체)*
3. 익명 표식의 색 확장 *(도형 6개만 사용)*
4. 실험 조건 축소 *(4개 → 2개: 150m / 300m)*

**포기 순서 맨 아래 — A(Redis) 구현.** 반나절~하루짜리이고,
두 구현을 비교하는 것이 실험 2의 내용이므로 밀려도 끝까지 붙잡는다.

**절대 포기하지 않는 것** — 신고·차단·EULA·개인정보처리방침.
이 넷은 빠지면 심사를 통과하지 못해 출시 자체가 불가능하다.
