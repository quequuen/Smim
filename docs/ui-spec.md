# UI 구현 명세

시간 표기, 익명 표식, 색·타이포 토큰, React Native 옮길 때 주의점.

- 시안: 스밈 화면 시안 (캔버스)
- 관련 결정: **D2**(반경) · **D4**(표식)
- 최종 수정: 2026-09-23

---

## 1. 시간 표기

### 1-1. 원칙

> **날짜가 주 라벨, 현재 기준 경과가 보조.**

```
────── 2025년 4월 12일 ──────
        1년 5개월 전
```

- **날짜** — 변하지 않는 사실. 계절 맥락을 담는다 (4월 = 벚꽃)
- **경과** — 지금 시점의 해석. "얼마나 된 거야"에 즉답한다

둘 다 **가운데 정렬**해 하나의 도장처럼 읽히게 한다.

### 1-2. 직전 블록 기준으로 쓰지 않는다

`8개월 후` 같은 표기는 쓰지 않는다. 이유가 셋이다.

| | 문제 |
|---|---|
| **스크롤 방향** | 채팅 스크롤은 위로 올릴수록 과거다. "N 후"는 아래로 내려올 때만 성립한다 |
| **체인 의존** | 앞 라벨을 알아야 현재 위치를 안다. 중간부터 읽으면 해석 불가 |
| **질문 불일치** | 사용자가 궁금한 건 "두 글 사이 간격"이 아니라 "이게 얼마나 된 건가"다 |

### 1-3. 포맷

| 조건 | 주 라벨 | 보조 |
|---|---|---|
| 오늘 | `2026년 9월 23일` | `오늘` |
| 어제 | `2026년 9월 22일` | `어제` |
| 7일 이내 | `2026년 9월 18일` | `5일 전` |
| 1년 이내 | `2025년 12월 3일` | `9개월 전` |
| 1년 이상 | `2025년 4월 12일` | `1년 5개월 전` |

주 라벨은 **항상 `YYYY년 M월 D일`** 로 고정한다. 오늘·어제도 날짜를 그대로 쓴다.

### 1-4. 보조 라벨은 클라이언트가 계산한다

서버는 `created_at`(TIMESTAMPTZ)만 내려준다.

> 서버가 "9개월 전"을 만들어 보내면, 앱이 백그라운드에 오래 머물렀을 때 값이 굳는다.
> **렌더링 시점에 앱이 계산**해야 정확하다.

### 1-5. 큰 공백은 색이 아니라 여백으로

직전 블록과 **3개월 이상** 벌어지면 구분선 위 여백을 넓힌다.

```
기본     margin-top  14
큰 공백  margin-top  56
```

색을 쓰지 않는 이유 — 색은 "중요하다"를 뜻하고, 여기서 전하려는 건 "멀다"다.
**시간 거리를 공간 거리로** 표현하면 은유가 맞고, 스크롤로 넘기는 데 실제로 더 오래 걸린다.

여백 값(14 / 56)은 **실제 데이터로 스크롤을 채워본 뒤 조정**한다.

## 2. 익명 표식 (D4)

### 2-1. 체계

**도형 6 × 색 4 = 24가지.**

```
도형  ●  ▲  ■  ◆  ★  ⬢
색    틸 · 클레이 · 앰버 · 슬레이트
```

- **도형을 먼저 다 쓴 뒤 색을 더한다.** 색각 이상이 있어도 도형만으로 구분되어야 한다
- 한 구간에 24명을 넘기면 그 이후는 표식 없이 표시한다
- **내 글에는 표식을 붙이지 않는다.** 오른쪽 정렬로만 구분한다

### 2-2. 배정과 저장

작성 시점에 확정해 `message.marker`(0~23)에 **저장**한다. 조회할 때마다 계산하면 같은 대화를
다시 봐도 기호가 달라진다.

```
1. 같은 구역 · 최근 marker_window_hour(기본 6h) 내 메시지 조회
2. 같은 author_key 가 이미 있으면 → 동일 표식
3. 없으면 → 미사용 표식 중 배정 (도형 우선, 색 나중)
4. 6시간 이상 끊기면 새 구간 → 표식 초기화
```

구분선 위아래의 같은 기호는 **서로 다른 사람**이다. 구분선이 경계를 그리므로 전역 유일성은 필요 없다.

### 2-3. 표식은 문자가 아니라 SVG로 그린다

> **`●▲■◆★⬢` 를 텍스트로 쓰지 말 것.**

기기·OS 폰트에 따라 이모지로 렌더링되거나(★ 특히), 글리프가 없거나(⬢),
크기·베이스라인이 제각각이 된다. 안드로이드 버전별 편차가 크다.

`react-native-svg` 로 직접 그리면 크기·색·정렬이 기기와 무관하게 고정된다.

## 3. 토큰

### 3-1. 색

| 역할 | 라이트 | 다크 |
|---|---|---|
| 배경 | `#F7F5F0` | `#14120F` |
| 표면 (입력창·카드) | `#FFFFFF` | `#1C1915` |
| 잉크 (내 글·제목) | `#1A1814` | `#EDE8DF` |
| 본문 · 날짜 | `#4A453D` | `#C5BDB0` |
| 보조 | `#6E675C` | `#968D80` |
| 선 | `#E2DDD2` | `#2F2A23` |
| 연한 선 | `#EDE9E1` | `#241F1A` |

**표식 4색**

| | 라이트 | 다크 |
|---|---|---|
| 틸 | `#2A7268` | `#5FC3B4` |
| 클레이 | `#9E4E2C` | `#E0916A` |
| 앰버 | `#806115` | `#D4B155` |
| 슬레이트 | `#5A6B7A` | `#8DA3B5` |

> **채도 있는 색은 표식에만 쓴다.** 본문·버튼·구분선이 전부 무채색이라
> 표식이 기능적으로 먼저 눈에 들어온다.

> **대비 기준** — 본문 4.5:1 이상. 위 값은 전부 충족한다.
> 흐린 회색을 더 흐리게 쓰고 싶어도 `#6E675C`(5.16:1)보다 밝게 가지 않는다.

### 3-2. 타이포

| 용도 | 서체 | 크기 | 자간 |
|---|---|---:|---|
| 본문 | Gothic A1 | 15 / 1.6 | — |
| 내 글 | Gothic A1 500 | 15 / 1.6 | — |
| 인용 | Gothic A1 | 12.5 / 1.45 | — |
| 구분선 날짜 | IBM Plex Mono | 11 | 0.1em = **1.1px** |
| 구분선 보조 | IBM Plex Mono | 10 | 0.1em = **1.0px** |
| 표식 | (SVG) | 12 | — |
| 헤더 라벨 | IBM Plex Mono | 12 | 0.14em = **1.68px** |
| 섹션 라벨 | IBM Plex Mono 600 | 10.5 | 0.16em = **1.68px** |

RN의 `letterSpacing` 은 **px 단위**다. `em` 값에 폰트 크기를 곱해 넣는다.

### 3-3. 간격

```
화면 좌우 패딩   20
헤더 높이        56
메시지 사이      11
표식 ↔ 본문      10
구분선 기본      위 14 · 아래 14
구분선 큰 공백   위 56 · 아래 14
터치 영역        44 이상
```

## 4. React Native로 옮길 때

### 4-1. 그대로 되는 것

Flexbox 레이아웃, 색, 크기, 여백, 정렬, `borderRadius`, 절대 위치 오버레이.
시안의 `display:flex` / `gap` / `flexGrow` 구조가 거의 1:1로 옮겨진다.

`gap` 은 RN 0.71+ 에서 지원한다 (Expo SDK 50 이상이면 문제없다).

### 4-2. 손봐야 하는 것

| 항목 | 웹 시안 | RN |
|---|---|---|
| **폰트** | Google Fonts `<link>` | 폰트 파일을 번들해야 한다. `expo-font` + `@expo-google-fonts/*`, 없으면 `.ttf` 직접 포함 |
| **아이콘** | 인라인 `<svg>` | `react-native-svg` 의 `<Svg><Path/></Svg>`. **path 데이터는 그대로** 쓸 수 있다 |
| **표식** | 유니코드 문자 | **SVG 도형으로** (→ 2-3) |
| **1px 선** | `height: 1px` | `StyleSheet.hairlineWidth` — 기기 밀도에 맞는 실제 1픽셀 |
| **자간** | `0.1em` | px 숫자로 환산 (→ 3-2) |
| **줄바꿈 금지** | `white-space: nowrap` | `<Text numberOfLines={1}>` |
| **입력창** | `<input>` | `<TextInput>` + `KeyboardAvoidingView` |

### 4-3. 스크롤 구조

날짜 블록이 곧 섹션이므로 **`SectionList`** 가 자연스럽다.

```
section         하나의 날짜 블록
renderSectionHeader   구분선 (날짜 + 경과)
renderItem            메시지 한 줄
```

> **주의** — 채팅 스크롤은 보통 `inverted` 로 뒤집는데, `SectionList` 를 뒤집으면
> 섹션 헤더가 항목 아래로 간다. 섹션 데이터를 역순으로 만들어 보정하거나,
> `inverted` 없이 최초 렌더 후 맨 아래로 스크롤하는 방식 중 하나를 골라야 한다.
> **4주차에 실기기로 확인할 항목.**

### 4-4. 한글 줄바꿈

웹에서는 `word-break: keep-all` 로 어절 단위 줄바꿈을 강제했지만
**RN에는 대응 속성이 없다.** 긴 문장이 어색하게 끊길 수 있다.

기기에서 직접 보고 판단할 항목이며, 문제가 되면 어절 사이에 U+2060(word joiner)을
넣는 방식으로 우회한다. 시안 단계에서 판단하지 말 것.
