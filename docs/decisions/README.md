# 설계 결정

구조를 규정하는 결정을 하나씩 기록한다. 숫자 값(반경 300m, 하트비트 45초 등)은
실험으로 바꿀 수 있지만, **여기 적힌 것들은 바꾸려면 스키마와 앱을 함께 갈아야 한다.**

| | 결정 | 상태 |
|---|---|---|
| [D1](D1-user-centered-radius.md) | 반경의 중심은 사용자다 — 격자로 나누지 않는다 | 확정 |
| [D2](D2-fixed-radius.md) | 반경은 밀도에 따라 바뀌지 않는다 — 기본 300m | 확정 (초안 번복) |
| [D3](D3-no-expiry.md) | 메시지는 만료되지 않는다 | 확정 (초안 번복) |
| [D4](D4-anonymous-marker.md) | 이름은 없고, 구간 표식만 있다 | 확정 (초안 번복) |
| [D5](D5-hybrid-delivery.md) | 실시간 전달과 영구 저장을 동시에 수행한다 | 확정 |
| [D6](D6-reaction-over-relationship.md) | 관계 대신 반응으로 재방문을 만든다 | 확정 |
| [D7](D7-time-labeling.md) | 시간은 날짜를 주 라벨로, 경과를 보조로 표기한다 | 확정 (초안 번복) |

## 형식

각 문서는 다음 순서로 쓴다.

```
상황      무엇을 정해야 했나
결정      무엇으로 정했나
대안      무엇을 버렸고 왜
결과      이 결정이 다른 곳에 무엇을 강제하나
번복      바꿀 수 있나, 바꾸려면 무엇을 건드려야 하나
```

**번복한 결정은 지우지 않고 그 안에 남긴다.** 왜 처음 생각이 틀렸는지가 결정 자체보다
설명력이 있는 경우가 많다. D2·D3·D4·D7이 그렇다.

## 바꾸기 쉬운 것과 어려운 것

| 난이도 | 항목 |
|---|---|
| **쉬움** — 서버 설정 | 반경 값, 유지 반경, 이동 임계값, 하트비트 주기, 표식 구간 길이 |
| **중간** — 서버 배포 | 신고 임계값, 정렬 방식, 알림 조건 |
| **어려움** — 스키마 + 앱 재배포 | **D1 · D3 · D4** |

D2는 값이 아니라 "밀도에 반응하지 않는다"는 원칙이므로 중간에 가깝다.
D7은 포맷이 `app/src/lib/time.ts` 한 곳에 모여 있어 쉬움에 가깝다.
