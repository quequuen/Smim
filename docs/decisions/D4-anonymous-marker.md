# D4. 이름은 없고, 구간 표식만 있다

> 확정 · 2026-09 · **초안을 두 번 번복한 결정**

## 상황

발화자를 어떻게 표시할지. 이름을 주면 대화가 읽히고, 안 주면 정체성이 안 생긴다.
그 사이 어디에 선을 그을지가 문제였다.

## 결정

이름도 닉네임도 화면에 없다. 대신 **도형 6종 × 색 4종**의 표식을 메시지에 붙이고,
표식은 **시간 구분선으로 나뉜 구간 안에서만** 유효하다.

```
도형  ● ▲ ■ ◆ ★ ⬢
색    틸 · 클레이 · 앰버 · 슬레이트    = 24가지

도형 = marker % 6      ← 도형을 먼저 다 쓴 뒤 색을 더한다
색   = marker / 6
```

서버는 `marker` 숫자(0~23)만 내려주고 도형·색 매핑은 앱이 한다.
**내 글에는 표식을 붙이지 않고 오른쪽 정렬로만 구분한다** — 남은 구분되지 않고 나만 구분된다.

## 대안 1 — 닉네임 (기각)

익명A/익명B든 사용자가 정한 이름이든.

**기각 이유** — 이름은 아무리 무의미해도 정체성을 만들고, 정체성은 관계를 만든다.
그러면 D1에서 벗어나려던 **사람 중심 구조로 되돌아간다.**

게다가 위치 기반이라 **같은 사람을 다시 만날 확률이 매우 낮다.**
닉네임을 붙여도 반복 접촉이 없으면 관계는 생기지 않는다.
결국 익명의 자유는 잃고 관계는 얻지 못하는, 가장 나쁜 절충이 된다.

## 대안 2 — 아무 표시도 없음 (기각)

가장 순수하고 구현이 0이다.

**기각 이유** — 여러 명이 동시에 말할 때 대화가 해독되지 않는다.

```
  여기 사람 진짜 많네요
  무슨 행사 있나요
  몰루
  버스킹 하는 듯
```

두 명인지 네 명인지 알 수 없다. 인용 답글이 있어도 여러 갈래가 섞이면 한계가 있다.

## 대안 3 — 장소별 고정 표식 (기각)

같은 장소에 다시 오면 같은 표식을 받는 방식.

**기각 이유** — "이 동네 단골" 같은 정체성이 생긴다. 대안 1과 같은 문제다.

## 번복한 것 ① — 표식을 떼려 했다

초안:

> 최근 몇 시간 안의 메시지에만 표식을 붙이고, 시간이 지나면 떼어낸다.
> 대화가 기록으로 굳는 과정이 화면에 보인다.

연출로는 좋았지만 **논리가 틀렸다.**

> 지금 읽는 데 표식이 필요했다면, 3개월 뒤 읽는 사람에게도 필요하다.

필요해서 붙인 것을 나중에 떼면 그때 읽는 사람이 해독하지 못한다.
→ **표식은 메시지에 영구히 저장한다.** 대신 범위를 구간으로 한정해 정체성 축적을 막는다.

## 번복한 것 ② — 전역 유일성을 걱정했다

표식이 24개뿐이라 사용자가 많으면 부족하다고 봤다.

**전역에서 유일할 필요가 없다.** 한 화면 구간에 동시에 등장하는 발화자는 대개 3~6명이고,
시간 구분선이 이미 대화의 경계를 그리고 있다.

```
──── 2025년 4월 12일 ────
  ● 여기 벚꽃 미쳤다
  ▲ ㄹㅇ 지금이 절정인 듯

──── 2025년 12월 3일 ────
  ● 지금은 눈 옴 ㅋㅋㅋ      ← 위의 ● 와 다른 사람
```

구분선을 사이에 두고 같은 기호가 나와도 동일인으로 오해하지 않는다.

## 결과

### 서버는 익명이 아니라 가명을 다룬다

삭제·차단·도배 방지는 내부 식별자 없이 구현할 수 없고, **차단은 스토어 심사 필수 요건**이다.

> **화면에 표시하지 않는다. 서버는 안다.**
> 완전 익명(anonymous)이 아니라 **가명(pseudonymous)** 이며, 개인정보처리방침에도 그렇게 쓴다.

기기가 만든 32바이트 난수를 `X-Device-Key`로 보내고, 서버는 SHA-256 해시만 `author_key`로 저장한다.
원본 키는 어디에도 저장하지 않는다.

### `author_key`는 어떤 응답에도 넣지 않는다

내려주는 순간 클라이언트가 같은 사람의 글을 묶을 수 있게 되어 무기명이 무너진다.

| 필요한 것 | 노출 대신 |
|---|---|
| 내 글 구분 | `isMine: boolean` (서버가 계산) |
| 차단 대상 지목 | 클라이언트가 **메시지 id**를 보내면 서버가 작성자를 찾는다 |

**대가** — 차단 목록에서 "누구를 차단했는지" 보여줄 것이 없다.
차단 시점의 메시지 내용을 함께 보여주는 정도가 최선이다.

### 표식은 계산하지 않고 저장한다

조회할 때마다 계산하면 같은 대화를 다시 봐도 기호가 달라진다.

```sql
marker  SMALLINT NOT NULL CHECK (marker BETWEEN 0 AND 23)
```

작성 시점에 같은 구역의 최근 6시간 내 메시지를 조회해 사용 중인 표식을 피해 배정한다.

> 이 배정에는 **동시성 문제**가 있다. 두 요청이 같은 순간 같은 구역에 쓰면 같은 표식을 받을 수 있다.

### 도형은 SVG로 그린다

`●▲■◆★⬢`를 텍스트로 렌더링하면 기기·OS 폰트에 따라 `★`이 컬러 이모지로 바뀌거나
`⬢`의 글리프가 없거나 베이스라인이 제각각이 된다. `react-native-svg`로 직접 그린다.

## 번복

**어렵다.** 표식 체계를 바꾸면 `marker` 컬럼의 의미가 달라져 기존 데이터를 해석할 수 없다.

닉네임을 도입하는 것은 기술적으로는 컬럼 하나지만, D1·D6과 함께 무너지는 결정이다.
