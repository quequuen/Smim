# D3. 메시지는 만료되지 않는다

> 확정 · 2026-09 · **초안을 번복한 결정**

## 상황

"지금 이 공간의 대화"라는 컨셉에서 출발했으므로, 메시지에 수명을 둘지 정해야 했다.

## 초안 — TTL로 자동 삭제 (폐기)

> 일정 시간이 지나면 오래된 메시지를 만료시킨다.
> 영구 기록이 아니라 "현재 공간에서 벌어지는 실시간 대화"라는 성격을 강화한다.

일반 메신저와의 차별화가 선명하고, 저장 부담도 없다.

**폐기 이유 — 콜드 스타트에서 치명적이다.**

주변에 아무도 없을 때 쓴 첫 메시지가 **아무에게도 읽히지 않고 사라진다.**

```
사용자가 첫 글을 쓴다
  → 주변에 아무도 없다
  → 반응이 없다
  → TTL 로 사라진다
  → 그 사용자는 다시 오지 않는다
```

빈 화면보다 이게 더 나쁘다. 사용자 수가 적은 초기에 정확히 이 상황만 반복된다.

## 결정

메시지는 좌표에 **영구히 남는다.** TTL 없음.

```sql
CREATE TABLE message (
    location   GEOGRAPHY(POINT, 4326) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    status     VARCHAR(16) NOT NULL DEFAULT 'visible',   -- 삭제는 상태로
    ...
);
```

**콜드 스타트를 동시 접속자 수가 아니라 시간으로 해결한다.**
첫 사용자 한 명의 글도 한 달 뒤 그 자리를 지나는 사람에게 읽힌다.

> 사용자 수가 아니라 **경과 시간이 서비스의 자산**이 되는 구조다.

## 결과

### 좋아진 것

- **빈 화면의 의미가 바뀌었다.** 아무도 없는 자리에 처음 쓰는 것이 이탈 사유가 아니라
  참여 동기가 된다 — 등산로 정상 방명록에 첫 번째로 이름을 적는 것과 같다
- D2에서 반경을 고정할 수 있게 된 근거다. 시간이 화면을 채우므로 공간을 넓힐 필요가 없다
- 재연결 시 미수신 복구가 단순해졌다. 마지막 수신 시각 이후를 조회하면 끝이다

### 나빠진 것 — 모더레이션 난이도

TTL이 있을 때는 문제 있는 글이 저절로 사라졌다. 이제는
**특정 좌표에 악의적인 글이 영구히 고정된다.** 누군가의 집 앞, 특정 가게에 비방 글을
남기면 그것이 그 장소의 고정 콘텐츠가 된다.

이것이 선례(Yik Yak)를 무너뜨린 원인이다. 그래서 모더레이션을 부가 기능이 아니라
**출시 요건**으로 재분류하고 일정을 앞당겼다.

- 신고 → 즉시 블라인드 → 검토
- 신고 누적 시 **자동** 블라인드 (1인 운영이라 수동 24시간 대응이 불가능하다)
- 좌표 단위 작성 금지 구역을 등록할 수단

### 파생된 UI 요구

기록이 몇 달·몇 년에 걸치므로 **시간 구분선**이 필수가 됐다.
날짜만 나열하면 어디서 크게 건너뛰었는지 보이지 않아, 큰 공백은 여백으로 표현한다.
→ [D7. 시간 표기](D7-time-labeling.md)

## 번복

**어렵다.** 되돌리면 이 서비스의 핵심 가치가 사라진다.

기술적으로는 `created_at` 기준 정리 배치를 돌리면 되지만, 그 순간 D2(반경 고정)의 근거가
무너지고 콜드 스타트 문제가 돌아온다. D2·D3는 함께 움직이는 한 쌍이다.
